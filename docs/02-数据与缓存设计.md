# CoinClock 数据与缓存设计

版本：0.1 · 日期：2026-09-21 · 与 [总体设计](01-技术总体设计.md) 和 [API 契约](03-API接口契约.md) 配套

本文件定义服务端的持久化真相、行情时序数据、用户配置、账务和缓存边界。缓存、搜索索引、客户端 SQLite 都是派生数据，任何余额、权限、提醒触发事实和收费流水都必须能够从持久化记录重建。

## 1. 全局约定

| 项目 | 约定 |
|---|---|
| 数据库 | PostgreSQL 16+，版本在立项时锁定；迁移用 Flyway，生产只前滚 |
| ID | 应用生成 UUIDv7；外部订单号另存，不用自增 ID 暴露数据规模 |
| 时间 | timestamptz，内部 UTC；原始行情同时保存 source_ts 和 received_at；前端按 IANA 时区展示 |
| 金额/价格 | numeric 或字符串化 Decimal；订单、账本、链上原子单位禁止 float/double |
| 精度 | 资产/币对保存 price_scale、quantity_scale、min_step；按场所元数据量化，拒绝隐式四舍五入 |
| JSON | 只存扩展、原始响应、版本化配置；参加查询/唯一性/扣费的数据必须有结构化列 |
| 删除 | 用户数据按政策软删/匿名化；账本、触发事实、审计不可物理删除或改写 |
| 审计 | 写入 audit_log 和 request_id；敏感旧值/新值只存摘要或加密快照 |
| 租约 | 所有分布式 Worker 使用 fencing token；Redis TTL 锁不代替数据库约束 |
| 隔离 | 业务、账务、审计可分 schema；读副本不用于权威写入或余额判断 |

直接删除旧行情表而没有对象存储清单、校验和与回放文档，视为不可接受的数据丢失。

## 3. 核心业务表

### 3.1 用户、设备和会话

| 表 | 关键字段 | 约束/索引 | 说明 |
|---|---|---|---|
| users | id、status、locale、timezone、created_at、deleted_at | status；登录 subject 唯一 | 业务 profile；OIDC 原始 subject 在 user_identities |
| user_identities | id、user_id、issuer、subject、provider、email_hash、verified_at | issuer + subject 唯一 | 不把 email 当永久主键 |
| user_devices | id、user_id、platform、app_version、install_id_hash、last_seen_at、revoked_at | user_id + install_id_hash；活跃索引 | 设备实例；切换账号要撤销会话和推送 |
| notification_endpoints | id、device_id、channel、endpoint_ciphertext、token_hash、status、last_error_at | device_id + channel；token hash 唯一 | endpoint/token 按渠道加密或哈希 |
| user_sessions | id、user_id、device_id、refresh_family、refresh_hash、expires_at、revoked_at | refresh_hash 唯一；user_id + status | 只存 refresh 哈希；复用时吊销 family |
| user_preferences | user_id、quiet_hours_json、default_venue、privacy_json、version | PK user_id；CAS version | 时区使用 IANA，规则级设置优先 |

### 3.2 场所、资产与行情

| 表 | 关键字段 | 约束/索引 | 说明 |
|---|---|---|---|
| venues | id、code、market_type、region、status、metadata_json | code 唯一 | EXCHANGE_SPOT、DEX_PERP 等能力声明 |
| assets | id、symbol、chain_id、contract_address、decimals、status | chain_id + contract_address 唯一；symbol 非唯一 | 同 symbol 的不同链/合约必须分开 |
| instruments | id、venue_id、base_asset_id、quote_asset_id、symbol、price_scale、quantity_scale、min_step、status | venue_id + symbol 唯一 | 规则和订单绑定此 ID |
| instrument_aliases | instrument_id、source、source_symbol | source + source_symbol 唯一 | 场所原始符号映射 |
| market_quotes_latest | instrument_id、price_type、price、source_ts、received_at、sequence、quality、source | instrument_id + price_type 主键 | 最新快照，可由事件重建 |
| market_candles | instrument_id、interval、bucket_start、open/high/low/close、volume、trade_count、source_revision | instrument_id + interval + bucket_start 主键 | 1m/5m/1h/1d，最终 candle 版本化 |
| market_quality_events | instrument_id、event_type、source_ts、details_json | instrument_id + source_ts；按月分区 | GAP、STALE、JUMP、RECONNECT 等 |

market_quotes_latest 只用于展示和恢复基线。提醒触发保存来源 tick 的 event_id、价格、时间和 quality，不能因快照覆盖而丢失事实。高频原始 tick 按日/小时写 TimescaleDB hypertable 或归档到对象存储；S0 低流量可使用热表，但要先定义分区、保留期和归档任务。

### 3.3 自选与价格提醒

| 表 | 关键字段 | 约束/索引 | 说明 |
|---|---|---|---|
| watchlists | id、user_id、name、sort_order、version | user_id + sort_order | 用户自选分组 |
| watchlist_items | watchlist_id、instrument_id、sort_order | watchlist_id + instrument_id 唯一 | 自选条目 |
| alert_rules | id、user_id、instrument_id、price_type、direction、trigger_mode、threshold、repeat_policy、hysteresis_bps、cooldown_seconds、expires_at、status、activation_status、version、cycle_no、baseline_price、armed_at、last_triggered_at | instrument_id + status + activation_status；user_id + status | version 每次编辑递增；状态机唯一真相 |
| alert_rule_devices | rule_id、device_id、enabled | rule_id + device_id 唯一 | 仅选择指定设备时使用 |
| alert_rule_revisions | rule_id、version、config_json、changed_by、changed_at | rule_id + version 主键 | 规则快照，便于审计和重放 |
| alert_triggers | id、rule_id、rule_version、cycle_no、event_id、trigger_price、threshold、price_type、source_ts、received_at、reason、status | rule_id + rule_version + cycle_no 唯一 | 触发不可更新，确认时间可追加 |
| alert_checkpoints | shard_id、kafka_partition、offset、last_event_id、saved_at、fencing_token | kafka_partition + offset | 分片恢复点 |

编辑使用 If-Match 或 expected_version。CAS 失败返回 409，禁止最后写入静默覆盖另一设备的规则。建议状态为 DRAFT → ACTIVE → TRIGGERED / WAIT_REARM / COMPLETED；ACTIVE 可转 PAUSED，过期为 EXPIRED，删除标记 DELETED。activation_status 单独为 PENDING / READY / STALE / ERROR。

### 3.4 通知与交付

| 表 | 关键字段 | 约束/索引 | 说明 |
|---|---|---|---|
| notifications | id、user_id、trigger_id、type、title_template、body_ciphertext、deep_link、expires_at、status、created_at | user_id + created_at；trigger_id 唯一（重复提醒另设序号） | 内容最小化，详情 API 再权限过滤 |
| notification_deliveries | id、notification_id、device_id、channel、provider_message_id、status、attempts、next_attempt_at、last_error_code、accepted_at、received_at、opened_at | notification_id + device_id + channel 唯一；待发送索引 | worker 幂等推进，允许 UNKNOWN |
| notification_receipts | delivery_id、event_type、occurred_at、payload_hash | delivery_id + event_type 唯一 | Provider webhook、客户端 ACK 追加事件 |
| notification_preferences | user_id、channel、enabled、quiet_hours_json、version | user_id + channel 唯一 | 客户端权限是观测值，不是服务端承诺 |

触发与通知分开，发送失败不能重建触发。notification_deliveries 只能证明供应商或客户端阶段回执，不能证明一定响铃。

| entitlement_events | id、entitlement_id、event_type、quantity、reference_type、reference_id、created_at | reference_type + reference_id + event_type 唯一 | 发放、预留、消耗、释放、撤销 |
| ledger_accounts | id、owner_type、owner_id、asset_code、account_type、status | owner + asset + type 唯一 | 可用/预留/应收/收入/退款 |

| ledger_entries | id、transaction_id、account_id、debit、credit、asset_code、amount | transaction_id + account_id；借贷校验 | 每笔事务总借等于总贷，只追加 |
| payment_quotes | id、user_id、purpose、chain_id、token_contract、atomic_amount、decimals、recipient、nonce、expires_at、status | quote nonce 唯一；有效期索引 | 固定价格、链、用途、收款方 |

所有平台服务额度/平台币内部可用量变化，必须在一个事务中写账本和业务引用；不允许只执行 UPDATE balance = balance - x。余额是分录聚合或经过校验的物化快照。每夜校验总额、悬挂预留、负可用余额和链上支付差异。

### 3.8 随机解锁专项表（后续，不是 S0/S1 依赖）

| 表 | 关键字段 | 约束/索引 | 说明 |
|---|---|---|---|
| `draw_pool_policy_versions` | `id`、`pool_code`、`version`、`opens_at`、`closes_at`、`cost_asset`、`cost_amount`、`probability_json`、`pity_rules_json`、`status` | `pool_code + version` 唯一；生效窗口不可重叠 | 概率/保底/费用不可覆盖，发布需审批 |
| `draw_pool_items` | `policy_version_id`、`analyst_version_id`、`rarity`、`weight`、`duplicate_policy` | policy + analyst 唯一 | 结果资产和重复规则 |
| `draws` | `id`、`user_id`、`pool_policy_version_id`、`payment_id`、`request_id`、`rng_commitment`、`rng_provider`、`result_hash`、`status` | `user_id + request_id` 唯一 | 抽取请求和可验证随机承诺 |
| `draw_results` | `draw_id`、`analyst_version_id`、`rarity`、`duplicate_action`、`entitlement_event_id` | draw 唯一 | 结果与权益发放分开，便于异常补偿 |

抽取失败先释放/退款，再允许同一幂等请求重试；结果已确定但发放失败时由 `entitlement_event_id` 对账补发，不能重新抽一次。概率变更只能新建 policy version，不能修改历史卡池。

## 4. 推荐 DDL 片段

以下只展示关键约束，真实迁移需补审计、分区、表注释和权限；numeric 精度按资产元数据校验。

~~~sql
create table alert_rules (
    id                 uuid primary key,
    user_id            uuid not null references users(id),
    instrument_id      uuid not null references instruments(id),
    price_type         text not null check (price_type in ('LAST','MARK','INDEX')),
    direction          text not null check (direction in ('ABOVE','BELOW')),
    trigger_mode       text not null check (trigger_mode in ('CROSS','LEVEL_ONCE')),
    threshold          numeric(38, 18) not null check (threshold > 0),
    repeat_policy      text not null check (repeat_policy in ('ONCE','REARM')),
    hysteresis_bps     integer not null default 0 check (hysteresis_bps between 0 and 50000),
    cooldown_seconds   integer not null default 300 check (cooldown_seconds between 0 and 2592000),
    expires_at         timestamptz,
    status             text not null,
    activation_status  text not null,
    version            bigint not null default 1,
    cycle_no           bigint not null default 1,
    baseline_price     numeric(38, 18),
    created_at         timestamptz not null default now(),
    updated_at         timestamptz not null default now()
);

create unique index uq_alert_trigger_cycle
    on alert_triggers(rule_id, rule_version, cycle_no);

create table ledger_entries (
    id              uuid primary key,
    transaction_id  uuid not null references ledger_transactions(id),
    account_id      uuid not null references ledger_accounts(id),
    asset_code      text not null,
    debit           numeric(48, 24) not null default 0 check (debit >= 0),
    credit          numeric(48, 24) not null default 0 check (credit >= 0),
    created_at      timestamptz not null default now(),
    check ((debit = 0 and credit > 0) or (credit = 0 and debit > 0))
);
~~~

应用层在提交账本事务前校验同一 asset_code 借贷相等；数据库触发器或存储过程可以作为第二道保护，但复杂业务逻辑不能只藏在触发器中。生产迁移先在空库、影子库、只读副本演练，再允许写入。

## 5. 时序数据与分区

| 数据 | 热期 | 冷期 | 归档/删除 |
|---|---:|---:|---|
| 最新 quote | 7 天用于诊断 | 30 天 | 过期后保留质量摘要；完整 tick 视套餐/合规归档 |
| 原始 tick | 24-72 小时 | 7-30 天 | Parquet 压缩到对象存储；校验和 + manifest |
| 1m candle | 90 天 | 2 年 | 之后按产品与合规留存，删除有审计 |
| 1h/1d candle | 5 年以上 | 归档 | 面向用户历史，通常长期保留 |
| alert trigger/notification | 2 年以上 | 归档 | 用户历史与争议依据，不能按行情短期删除 |
| audit / ledger / payment | 按适用法律与争议期 | 加密冷存 | 只追加，不因账户删除而改写 |

分区键使用 source_ts 或业务 created_at，避免跨所有分区扫描。归档任务先标记、校验对象、写 manifest，再删除分区。恢复必须能重建规则基线和账务对账。

## 6. Redis 缓存设计

### 6.1 Key 表

| Key 模式 | 类型 / TTL | 内容 | 一致性与失效 |
|---|---|---|---|
| quote:{venue}:{instrument}:{price_type} | String JSON，5 秒 | price、source_ts、received_at、quality、sequence | 事件覆盖；过期即 STALE；不作账务来源 |
| quote:channel:{instrument} | Pub/Sub 或 Stream，短保留 | 最新广播引用 | 丢失可从 Kafka/PG 重建；不作唯一触发 |
| alert:active:{instrument} | Sorted Set / 规则索引 | 规则 ID 与上下阈值 | 规则事件版本化更新，缺失可回源重建 |
| alert:state:{rule_id} | Hash，最多 1 小时续期 | previous、baseline、armed、last seq、fencing | 只加速；checkpoint 在 PG/事件中 |
| session:refresh:{hash} | String 至过期 | family、user、device、状态 | 吊销主动删除；只存 hash |
| session:revoked:{user_id} | Set 至最长 session TTL | session/family 版本 | 权限缓存不可用时拒绝敏感操作 |
| entitlement:{user_id} | JSON，30-60 秒 | 有效权益摘要、policy version | 发放/撤销 Outbox 主动失效 |
| fee:policy:{version} | JSON 至政策退休+审计窗口 | 只读费率规则 | 历史版本永不覆盖 |
| rate:{scope}:{id}:{window} | Hash/Counter，窗口 TTL | API/AI/交易计数 | Lua 原子，超限返回 Retry-After |
| idempotency:{user}:{key} | String JSON，24-48 小时 | request hash、status、response | body 不同返回 409 |
| notify:dedupe:{event_id}:{device_id}:{channel} | String 至通知寿命+重试期 | delivery_id | PG 唯一键最终兜底 |
| lock:{resource} | String token，短 TTL | fencing token | 只降低竞争，不能绕过 DB 约束 |
| chain:cursor:{chain}:{contract} | Hash，短 TTL | last block/hash | 只读加速；权威 cursor 在 PG |

Redis key 不含原始 email、完整钱包、推送 token 或 AI 原文。多租户/环境使用 prod:cn1: 前缀，开发环境禁止连接生产。队列/锁与普通缓存混用时必须隔离 maxmemory/policy，最好拆实例。

### 6.2 读写规则

1. 详情和权益采用 cache-aside：miss 从主库读取再写短 TTL；写成功后发失效事件，缓存不可用不改变权限结果。
2. 行情采集器先验证事件，再更新 Redis 快照和 Kafka；PG 最新表由独立消费者写入。Redis 失败不能丢 Kafka，Kafka 失败则重试/断路。
3. 规则保存成功后由 Outbox 更新索引；索引版本落后时以 PG 为真重建，不能按陈旧索引触发。
4. 热 key 请求合并并加入随机 TTL；行情按 instrument 共享，权限和费率只预热必要用户。
5. 事务提交后发失效事件，消费者按 aggregate_version 丢弃旧事件；不在提交前删缓存并宣称成功。
6. Redis 清空后从 PG、Kafka 和当前行情重建；规则触发唯一键、账本和订单状态不依赖缓存。

令牌桶在一个 Lua 脚本中完成补充、扣减和 TTL 设置。Redis 超时后，写/交易/AI 拒绝或采用网关保守限流，不能无条件放行金融操作。幂等记录至少包括 body hash、首个响应、状态和创建时间；结果未知时返回 PROCESSING + status URL，不重复执行业务。

## 7. 事件与 Outbox

| Topic | Key | 事件 | 消费者 |
|---|---|---|---|
| market.quote.v1 | instrument_id | 标准化行情、quality | 规则、K 线、WS、质量监控 |
| alert.lifecycle.v1 | rule_id | activate/update/pause/trigger | 规则索引、通知、同步 |
| notification.delivery.v1 | delivery_id | create/retry/receipt | 通知 Worker、审计 |
| entitlement.lifecycle.v1 | user_id | grant/reserve/consume/revoke | 权益缓存、AI、计费 |
| trading.order.v1 | user_id/account | intent/submission/fill | 交易适配、持仓、计费 |
| chain.event.v1 | chain_id:contract | payment/NFT/finality/reorg | 支付、权益、对账 |
| ai.run.v1 | run_id | queued/running/completed/failed | AI Worker、WS、用量 |

事件 envelope 包含 event_id、event_type、version、occurred_at、producer、trace_id、aggregate_type、aggregate_id、aggregate_version、payload。消费者记录 inbox/offset 或领域唯一键；破坏性变化升 major topic/version。

业务事务写主表与 outbox_events，发布器带 claim/fencing 投递；消费者先落 inbox/业务事实，再提交 offset。重复投递可接受，重复业务效果不可接受。死信重放需管理员审批和原始 trace。

## 8. 备份、恢复和数据质量

- PostgreSQL：每日全量 + 连续 WAL/PITR，跨可用区和灾备区加密；目标 RPO ≤ 5 分钟、RTO ≤ 60 分钟，必须实演。
- Redis：派生缓存不以备份为恢复目标；session/限流清空后重新授权/限流，账务和规则从主库重建。关键 Stream 必须拆实例或另设持久化。
- Kafka：关键事件保留至下游确认和审计窗口，原始行情归档对象存储。
- 对象存储：版本、WORM/保留策略、跨区域复制，报告和备份默认私有。
- 每月恢复主库、每季跨区演练，检查规则回放不重复、账本借贷相等、链重组可恢复、通知不会无限补发。
- 数据质量作业检查 instrument 元数据、价格 gap/乱序、candle OHLC、触发版本、delivery 超时、账本平衡、支付金额、NFT finality、AI 预留与结算。

## 9. 迁移与变更流程

1. 新表/索引先做兼容性增加，大索引并发创建。
2. 先部署可读旧/新字段的代码，再扩展写入；回填可暂停且有进度。
3. API 和事件 schema 使用双读/双写窗口，消费者升级后才删除旧字段。
4. 账务、费率、NFT 权益变更必须有 policy version、补偿计划和双人审批，不直接改分录。
5. 迁移失败回滚应用或执行补偿迁移；生产不依赖不可逆 down migration。
