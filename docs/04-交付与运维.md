# CoinClock 交付、运维与验收计划

版本：0.1 · 日期：2026-09-21

本文件把技术设计变成可排期的工程任务和可测量的上线门槛。工期是粗估，用于拆分依赖；应在现有代码盘点、团队规模和目标地区确认后重排。

## 1. 任务拆分

### 1.1 P0：现状盘点与技术基线（1-2 周）

| 工作包 | 交付物 | 依赖/验收 |
|---|---|---|
| 现有实现盘点 | 语言、入口、已有 alarm、行情源、部署和债务清单 | 代码、运行环境和真实请求均有证据；不能以截图代替 |
| 产品规则冻结 | 价格来源、触发语义、时区、重复/迟滞、通知寿命 | 10 个边界例子评审通过 |
| 五端壳工程 | Flutter 移动、Tauri 桌面、Web、共享 OpenAPI SDK | 五端可启动、登录、展示健康状态 |
| 环境与 CI | dev/staging/prod、秘密、镜像签名、迁移流水线 | 无生产凭据进仓库；可回滚制品 |
| 安全基线 | 威胁模型、数据分类、权限矩阵、隐私和删除策略 | API/数据库/运维访问清单与责任人 |

### 1.2 S0：多币种价格闹钟（4-8 周，按团队规模调整）

| 领域 | 任务 | 验收重点 |
|---|---|---|
| Identity | OIDC、PKCE、设备/会话、退出与撤销 | refresh 复用能吊销 family；跨端一致 |
| Market | 一个主行情源 + 目录、WS、K 线、质量状态 | 重连/乱序/gap 测试；价格来源清晰 |
| Alert | 规则 CRUD、CROSS/LEVEL、迟滞、CAS、版本 | 断流恢复不伪造触发；并发暂停/触发正确 |
| Engine | Kafka/Outbox、分区、checkpoint、回放 | 重放不重复业务触发；lag 可观测 |
| Notification | APNs/FCM/Web Push/桌面通道最小闭环 | token 失效、重试、dedupe、receipt |
| Client | 五端登录、自选、创建/暂停、历史、通知测试 | 真实设备验收；离线/权限/过期 UI 明确 |
| Ops | 指标、日志、trace、告警、备份恢复演练 | p95 可按 instrument/端/渠道分析 |

S0 不包含自动交易、平台币、NFT、随机解锁、收益承诺或自建撮合。若产品把“响铃”作为强制卖点，必须把通知资格、免打扰和硬件限制放入商店文案和验收，不能用服务端 SLO 代替系统保证。

### 1.3 S1：AI 分析师与权益（3-6 周）

- 分析师目录/版本、固定行情快照、模型网关、引用/报告存储。
- 权益、额度、会员服务额度、AI waiver、退款和失败释放。
- prompt injection 测试、工具 allowlist、输出 XSS/敏感信息扫描。
- 运行计量、成本预算、模型供应商熔断和质量抽样。

### 1.4 S2：非托管交易与链上权益（8-16 周以上）

- 钱包挑战/绑定、WalletConnect/深链、EVM/目标场所适配、订单意图和签名。
- 场所行情/订单/成交/持仓对账；未知提交状态与撤单竞态。
- fee policy、VIP 快照、平台服务费 ledger、quote/payment/finality/reorg。
- NFT 持仓索引、权益随持有变化、App Store/Play 收据适配。
- 交易 UI 增加过期数据、滑点、费用、风险和签名原文展示。

S2 的估算不包含牌照、法律意见、链/协议安全审计、正式市场做市和客服运营，这些是独立计划和成本。

### 1.5 S3：自建 DEX 预研与生产门槛（独立项目）

1. 规则与数学规格；2. 确定性撮合原型；3. 风险/清算仿真；4. 测试网与故障注入；5. 合约/客户端/基础设施审计；6. 受限资产与资金灰度；7. 审慎扩容。

在没有可重放撮合日志、资产守恒对账、退出/暂停方案、密钥与升级多签、极端行情仿真的情况下，不进入真实资金阶段。

## 2. 容量假设与扩展路径

以下是用于初版压测的假设，不是目标承诺：

| 量级 | S0 压测基线 | 扩展策略 |
|---|---:|---|
| 注册用户 | 100k | 账户/权益按 user_id 分片读，PG 读副本承载历史 |
| 日活 | 10k | API/BFF 无状态水平扩展 |
| 活跃规则 | 1M | instrument 分区；规则索引按阈值；冷热用户分层 |
| 行情更新 | 50k events/s 峰值 | Kafka 分区 + 采集器水平扩展；WS 只发订阅快照 |
| 规则检测 | 50k events/s，事件内 p95 < 500ms | 分区内有序、内存索引、批量 checkpoint；PG 只写触发和关键状态 |
| 触发事件 | 1k/s 突发 | Outbox/Kafka/通知队列削峰；供应商按通道限速 |
| AI 任务 | 10/s 初始 | 独立队列、用户/分析师并发、模型路由与成本熔断 |
| 交易请求 | 100/s 初始 | 账户/场所限速和串行未知状态查询；不因扩容绕过幂等 |

容量模型分开计算：events_per_sec × active_rules_per_instrument、消息大小、DB WAL、WS fanout、推送服务限额和第三方 RPC。上线前以真实 payload 做 2 倍峰值压测，再确定实例规格和分区数。交易/账务使用尾延迟与错误状态压测，不只看平均 QPS。

## 3. SLO、监控与告警

### 3.1 建议 SLO

| 指标 | 目标 | 备注 |
|---|---:|---|
| API 可用性 | 99.9%/月（公开行情读） | 认证/敏感写操作独立统计 |
| 规则写入后激活 | p95 ≤ 10s | Pending 状态可见 |
| 新鲜行情到规则判定 | p95 ≤ 2s，p99 ≤ 5s | 不含第三方行情源中断 |
| 触发到通知任务入队 | p95 ≤ 3s | 只承诺服务端接受任务 |
| 重复业务触发 | 0（同 rule/version/cycle） | 推送重复另按 delivery 观察 |
| 规则回放结果 | 与在线判定一致 | 版本、质量、fencing 可复现 |
| 账本平衡 | 每笔、每小时检查 0 差异 | 差异自动升高优先级 |
| 数据备份 | RPO ≤ 5m、RTO ≤ 60m | 以实演结果为准 |

移动系统、浏览器和供应商的展示时间不纳入服务端通知入队 SLO。产品和客服文案必须区分这两个时间点。

### 3.2 指标

- 行情：连接数、重连次数、source→received 延迟、sequence gap、STALE/SUSPECT/JUMP 数、每 instrument 最新年龄。
- 规则：活跃规则数、分片 lag、触发评估耗时、触发成功/冲突/跳过原因、checkpoint age、回放次数。
- 通知：按 channel/provider 的 accept/error/retry/expired、invalid token、receipt 延迟、dedupe 命中。
- API：按 route/status/code/client 的 QPS、p50/p95/p99、429、DB pool、Redis latency、Kafka lag。
- 交易：intent 创建、签名失败、外部接受/拒绝/未知、查询恢复时长、成交延迟、对账差异、费用策略版本。
- 账务：借贷差、可用负余额、悬挂预留、支付确认时间、链重组、NFT 权益差异。
- AI：队列深度、模型延迟/错误/超时、token/成本、预留与结算差、工具拒绝、报告质量抽样。
- 客户端：崩溃率、登录成功率、通知授权率、WS 断线、规则创建/激活漏斗、版本分布。

日志统一 JSON：timestamp、level、service、env、trace_id、request_id、user_hash、resource_id、event、code、latency_ms。生产默认不记录完整 prompt、签名、push token、地址、邮箱和费用原文。

### 3.3 告警分级

| 级别 | 例子 | 处理 |
|---|---|---|
| P0 | 资金守恒差异、错误发放/扣费、权限绕过、全量行情错误 | 立即冻结相关写入/费率，值班响应，保留证据 |
| P1 | 多分片规则停滞、通知队列积压、订单对账未知无法收敛 | 30 分钟内响应，按 runbook 降级 |
| P2 | 单场所断流、单通道推送故障、AI 供应商超时 | 自动熔断/切换，工作时间处理 |
| P3 | 单客户端版本崩溃、低比例错误 | 进入发布和版本修复队列 |

严禁把自动切换场所作为行情提醒默认恢复；必须在界面明确价格源变化，规则仍绑定原 instrument。

## 4. 测试计划

### 4.1 规则与行情

- 单元：above/below 边界、相等价格、首个 baseline、迟滞、冷却、过期、时区、精度、负/零输入。
- 属性/模型测试：随机序列在线引擎与离线参考实现一致；event replay 不重复触发。
- 集成：乱序、重复、断连、重连 gap、分区迁移、checkpoint 崩溃、PG commit 后进程崩溃。
- 负载：不同 instrument 分布、单一热门币、触发风暴、通知供应商限速。

### 4.2 API 与安全

- OpenAPI contract、五端生成 SDK 编译、错误码/字段兼容。
- 权限矩阵：跨用户 IDOR、WS 私有频道、设备切换、管理员越权、删除后访问。
- OIDC/PKCE、refresh 重放、CSRF/CORS、SSRF、XSS、文件上传、限流绕过、幂等键 body 替换。
- 钱包签名：domain/URI/chain/purpose/nonce/expiration 篡改；订单 payload hash/费用/收款地址变更。
- SAST/SCA/DAST、镜像扫描、SBOM、密钥扫描、桌面 capability 审查、移动 release 签名/公证。

### 4.3 交易、链上与账务

- 订单状态：外部超时、重复 callback、部分成交/撤单竞态、场所重启、精度/最小量、费率版本切换。
- payment：过期 quote、少付/多付/错 token/错 chain、重复 log、未 final、reorg、RPC 不一致、退款/收据撤销。
- NFT：转移、批量持有、链重组、钱包解绑、同 NFT 多账号、权益到期。
- 账本：事务重试、并发预留、释放、退款、异常负余额；随机抽样和全量借贷平衡。

### 4.4 五端真实设备验收

| 端 | 最低矩阵 |
|---|---|
| iOS | 两个主 iOS 版本；锁屏/后台/低电量/无通知权限/时区变化；TestFlight 签名 |
| Android | 两个主版本、Doze、精确闹钟权限、厂商电池策略、FCM token 轮换 |
| Windows | 安装/升级/卸载、休眠/锁屏、系统通知、代理、签名安装包 |
| macOS | 两个主版本、通知权限、休眠、Apple Silicon/Intel（若支持）、公证 |
| Web | Chrome/Edge/Safari/Firefox 支持范围、Service Worker 更新、Web Push 权限、跨标签登录 |

每个端至少验收：创建规则、跨端同步、断网恢复、触发去重、通知测试、ACK、暂停竞态、登出/换号、删除账户、版本升级后旧规则恢复。通知展示时间依系统能力记录为观测，不以人工“听到声音”作为唯一自动化断言。

## 5. 发布与回滚

1. PR：格式、单测、静态扫描、OpenAPI/事件兼容、迁移 lint、镜像 SBOM。
2. 合并：构建不可变镜像和五端制品，签名并上传制品库；部署 staging 自动迁移和集成测试。
3. 预生产：匿名/合成行情回放、通知 provider sandbox、链测试网、压测、恢复演练。
4. 生产：先部署兼容代码，再迁移，再逐步放量；feature flag 按用户/地区/客户端版本/场所开启。
5. 观察窗口：至少覆盖一个完整通知日和行情高峰；关注 SLO、规则 lag、账务差异、崩溃和权限日志。
6. 回滚：应用可回滚，事件 schema 向后兼容；费率/权益不直接回滚既有分录，使用补偿 policy/version；交易/支付未知状态先对账。

推送证书、Apple/Google 密钥、RPC/API key 和模型 key 由秘密管理器注入。生产发布角色不应同时拥有读取所有金融密钥和修改费率的权限。

## 6. Runbook 摘要

### 行情源断连

1. 标记受影响 instrument 为 STALE，停止新触发/交易（按策略），保留最后新鲜时间。
2. 检查连接、DNS、证书、供应商状态和 sequence gap；重连使用指数退避。
3. 恢复后丢失区间不推断穿越，首个有效 tick 建 baseline；补历史时单独回放并标注。
4. 通知受影响用户/运维；不要静默切换为另一价格源。

### 规则分片 lag

1. 保护 checkpoint，暂停非必要回放；检查分区倾斜、GC、Redis/PG latency。
2. 扩容或迁移 instrument，使用 fencing 防双主；回放用业务唯一键。
3. 若事件已超过通知寿命，记录 missed，不批量制造过时紧急通知。

### 支付/账本差异

1. 停止受影响 token/chain 的新 grant/扣款，保留只读查询。
2. 比对 quote、链事件 finality、reorg、ledger entries 和 entitlement events，生成差异清单。
3. 双人审批补偿/退款分录；修复不删除原事件。恢复前通过全量平衡和回放测试。

### 推送通道故障

1. 记录 provider 错误并按通道熔断/退避，站内通知和 WS 仍可用。
2. 失效 token 停用；不要把邮件/短信作为未经授权的默认 fallback。
3. 恢复后只重试未过期且用户仍允许的 delivery；用唯一键和 event_id 去重。

### 订单提交未知

1. 停止同一 intent 的再次提交，保留签名和 payload hash 审计。
2. 使用场所查询/WS 以 client_order_id 收敛；必要时人工核验官方状态。
3. 确认无订单/成交后才标记失败；有部分成交则按事实结算，不能凭超时假设全未成交。
